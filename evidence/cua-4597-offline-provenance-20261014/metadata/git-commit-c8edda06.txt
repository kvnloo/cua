fix(cua-driver): drain Windows foreground input before restoring focus (#4500)

Foreground type_text/press_key restored the previous foreground window a fixed 40 ms after SendInput, before slow-to-process targets had read the queued tail, so text after line breaks was lost (#4477). Attach to the foreground thread's input queue before inserting, append an unassigned-VK sentinel, and restore only after the target has read it (bounded at 2 s). Adds WPF/WinUI3 multiline fixtures with an app-owned state oracle and foreground single-line/multiline text tests.

Fixes #4477
