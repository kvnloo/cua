## R2-04 input for AT-SPI invalidation and R2-09 (no invalidation verdict)

Packet: [R2-04 README](https://github.com/kvnloo/cua/blob/exp/r2-04-atspi-profile-20261001/docs/experiments/r2-04-2026-10-01/README.md), packet HEAD `9bfd43739`. Independently verified and accepted.

This is **not** the invalidation-fidelity census this issue asks for. No false-negative, restart, reconnect or create/destroy rows were run, so no scope can be classified "safe invalidator" from it. The useful inputs are below. They come from the canonical GTK3 fixture in its opt-in 9-element task window, upstream main `229b65b28`, Driver 0.32.0, and a private AT-SPI bus and registry. All rows are REAL.

### Inputs

- **Event timing (descriptive).** The app's first signal after `Action.DoAction` (`StateChanged:checked`, `TextChanged` or `BoundsChanged`) arrived 0.1–0.5 ms after `DoAction`, seen on the bus with `dbus-monitor`. On the Save click, the first signal was `BoundsChanged`, not a note-specific signal. Event type does not reliably name the semantic change.
- **Fresh observation agreed with the app's own state file** in 80/80 checkbox trials and 80/80 text trials. This is a cross-layer check only; the state file was the oracle.
- **No caller-side post-action wait exists to delete on this fixture.** The app had already changed state ~299 ms before the tool call returned, and the caller's mutation wait was 0.05 ms. Event-driven skipping or waking therefore has no caller-side wait to save here.
- **The remaining waits are inside the Driver:**
  - a fixed 50 ms sleep after `DoAction` (`perform_action_ref`);
  - the focus guard's 220 ms settle watch (~241 ms restore).

  An app signal could wake the first early, but only after a causal A/B shows the sleep can be shortened. The settle watch guards against focus steal, and event absence cannot prove "no steal", so it is not an event-wake target.
- **Tree acquisition cost:** 145 RPCs, ~2.9 ms of bus time inside a ~26 ms call. That is ~16 RPCs and ~0.32 ms per emitted element. Large trees are untested.
- **Stale-token negatives:** 32/32 refused (`stale_element_token`), with 0 `DoAction` on the bus.

### Effect on this issue's plan

- The promotion gate is unchanged: no observation skipping without zero relevant false negatives for the claimed scope.
- R2-09 (native wake, kvnloo/cua#93) is deferred until the Driver-internal waits are shown causal.
- Unchanged: this census's mutation list still needs to run (create/destroy, process restart, bus reconnect).
