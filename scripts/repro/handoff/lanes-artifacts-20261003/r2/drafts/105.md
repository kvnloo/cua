## R2-05: real-transport evidence for the mutation-outcome receipt (KEEP, with runner gaps)

Packet: [R2-05 README](https://github.com/kvnloo/cua/blob/exp/r2-05-ack-loss-real-20261001/docs/experiments/r2-05-2026-10-01/README.md), packet HEAD `236e37e01`, pre-registration `6915dd75d`. Independently verified and accepted.

### What was tested

- **Caller:** the unmodified jev-use Python runner at this PR's head `98a45e6c5` (live head re-read at 23:15Z: unchanged, OPEN draft).
- **Driver:** 0.31.0, sha256 `e57bb9ae…`, built from trycua/cua PR 4316 at `a0bca7440`. That source is identical to this head outside `examples/`.
- **Session:** real MCP stdio transport, Chrome 151, private Xvfb.
- **Oracle:** the target-owned fixture journal.
- **Faults:** injected at an in-process seam between `ClientSession` and the real stdio streams.

### Results (REAL)

- A typed caller that follows the receipt made **0 duplicate mutations in 60 trials**. The receipt rule is "observe and reconcile on `unknown`; reconsider only when the mutation request's own write raised". The 60 trials cover control, pre-write failure, request lost, applied-but-ack-lost, delayed after one unchanged read, and delayed past the deadline.
  - Read this zero with care. The typed caller has no dispatch path after `unknown_effect`, so for 40 of those trials the zero holds by construction. The empirical content is listed in the packet.
- A naive restart-from-step-one **duplicated in 10/10 trials** when the original was still in flight (RD). 95% CI 0.692–1.000.
- **This PR's receipt reported `attempted=true, effect=unknown, retryDisposition=observe` in 20/20 RA trials.** That is safe. In the narrow case where the request's own write provably failed, it gives up a legal reconsideration.
- In RC the first reconciliation read was **negative 10/10** while the original was still in flight, and the journal then shows it landed. This is the real-path case where one negative read must not authorize a replay.

### Gaps in this PR, found by the experiment

1. **The runner does not reconcile (SOURCE).** On an action error, `run.py` writes `unknown` and returns. The bounded reconciliation and reconsideration that were measured are experiment code. Either move bounded reconciliation into the runner, or document that callers must do it.
2. **Nothing guards against a second completion while the first is unresolved (SOURCE + REAL probe).** In RE there was no replay only because Chrome's pending navigation made the next snapshot fail after ~100 s. That is not a safety proof. A targeted test needs a fixture that keeps Submit observable.
3. **A read failure after an unverified completion escapes uncaught**, so no receipt is written (RE 10/10 `DriverToolError`). Catch it and emit a receipt.
4. **The pre-write scope (UNIT + SOURCE).** In mcp 1.30.0, `ClosedResourceError` / `BrokenResourceError` from `call_tool` is **not** proof that a request was never written. `_validate_tool_result` calls `list_tools()` after a cache miss, and that call can raise after the effect has landed (extension case A). Any future `not_written` value needs evidence that the request's own write raised. That decision belongs to kvnloo/cua#38 and upstream trycua/cua 4009. No public field is proposed here.

### Not covered

TypeScript runner on a real transport, Driver crash or OS pipe cut, socket transport, cancellation (kvnloo/cua#9), idempotency rows, and any timing. The gates were registered after a one-trial-per-cell pilot, so they are not blind. This is not an exactly-once guarantee.
