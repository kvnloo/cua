### How the backend was identified

The harness wraps the runner with a measurement-only launcher. It records each provider HTTP attempt and each SDK response:
- host;
- status;
- whether a request id was present, and a hash prefix of it;
- model;
- token usage;
- the selected id.

It never records headers, bodies, typed text or the key. This is an attributed responder receipt equivalent to the `backend` field this issue asks for. It does **not** test trycua/cua PR 4394's code: that PR's head `039257811` was not run, and its S1 adapter is not available locally.

### Results (LIVE_PROVIDER + REAL)

- Receipts matched runner decisions in every trial. All responses were HTTP 200 with a request id from `api.typesafe.ai`, model `jev-1.13.0`. Baseline made 80 responses and guarded made 40, so 2 → 1 per task in 40/40 pairs.
- Configured intent was not counted as a decision. With the provider unreachable (C2, closed loopback port, 2/2), there were 0 successful responses, 0 Driver mutations and 0 verified outcomes.
- Mock runs show `backend=mock` with 0 HTTP attempts (C0), so a mock decision cannot pass as a live one.
- Guard declined: on the duplicate-Submit fixture (C1, 3/3), the guard declined with `submit_not_unique` and the provider handled both steps. Each run verified with exactly one submit.
